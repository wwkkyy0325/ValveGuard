# ValveGuard v1.0.0 Release Assets

Status: built by the release workflow from the repository source and the
committed ONNX bundle.

## Assets

| Asset | Contents |
|---|---|
| `valveguard_cnn_v1_onnx.zip` | CNN champion ONNX bundle: `model.onnx` (opset 17), manifest, channel names, human reference distributions, human player scores, README |
| `valveguard-desktop-v1-win64.zip` | Pure-Rust Tauri app, ONNX model, manifest, channel names, reference files, README |
| `*-setup.exe` | NSIS installer |
| `*.msi` | MSI installer |
| `SHA256SUMS.txt` | SHA256 for every uploaded asset |

The ONNX bundle is the deployed CNN champion (3 seeds x 5 folds,
hard-negative alpha=5). The desktop zip is the pure-Rust Tauri app with the
same ONNX bundle next to the executable; no Python sidecar.

## Model runtime

```bash
pip install -r requirements-onnx.txt
```

```python
from valveguard.models.onnx_artifact import load_onnx_detector

detector = load_onnx_detector("valveguard_cnn_v1_onnx")
scores = detector.score_channels(channels, names)
players = detector.aggregate(frame, scores)
```

`load_onnx_detector` does not import torch. The bundle manifest records
SHA256 checksums for every file and the loader rejects mismatches.

## Publishing on GitHub

Git and Releases have different jobs:

- **Git**: source, configs, manifests, checksums, docs, and README links.
- **Releases**: large binaries. Release assets do not bloat the git clone.

The release is built by `.github/workflows/release.yml` on a Windows runner.

### Model bundle

The deployed ONNX bundle is committed under
`artifacts/valveguard_cnn_v1_onnx/` (about 31 MB), so the workflow needs no
external model storage. Training checkpoints and packaged zips stay ignored.

### Cut a release

```bash
git tag v1.0.0
git push origin v1.0.0
```

Or run Actions -> Release -> Run workflow and enter the tag.

The workflow:

1. verifies the committed ONNX bundle;
2. runs `npm run tauri build -- --bundles nsis,msi`;
3. builds `valveguard-desktop-v1-win64.zip` (`ValveGuard.exe` + `model/`);
4. zips the model bundle as `valveguard_cnn_v1_onnx.zip`;
5. writes `SHA256SUMS.txt`;
6. creates the GitHub Release with the portable zip, the model zip, the
   NSIS installer, the MSI installer, and the checksums.

Stable URLs:


Manual fallback, if Actions is unavailable:

```bash
gh release create v1.0.0 \
  artifacts/valveguard_cnn_v1_onnx.zip \
  artifacts/valveguard-desktop-v1-win64.zip \
  --title "ValveGuard v1.0.0" \
  --notes-file docs/releases/v1.0.0.md
```

## What is committed

- The unpacked ONNX bundle (`artifacts/valveguard_cnn_v1_onnx/`, about
  31 MB) is committed so the release workflow is self-contained and does
  not depend on external model hosting. This is the one deliberate binary
  in git.
- Training checkpoints, packaged zips, and the portable app archive stay
  ignored; they are either large or reproducible.
- A new model version should replace the committed bundle and bump the
  artifact name, not accumulate copies.
